# 《后来呢》实施与验收清单

本清单保留原始验收要求。2026-10-24 已实现全剧情可玩版；当前实现及实际验证范围见 [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md)。以下“文档包当前范围”是最初设计阶段的范围说明，不代表当前源码仍未实现。

## 文档包当前范围

- 正式游戏名《后来呢》，主角小五、小梦。
- 完整 33 节点分场剧本及 4 种结局。
- 基于当前 SECOND NATURE 源码特点的迁移/改写方案。
- 每节点的画面、时间、地点、人物阶段、道具与分支变化说明。
- 27 类基础构图、29 张基础背景文件的制作规划。
- 结构化场景索引；图文件状态全部为 planned。
- 尚未编程、批量绘图、配音、试玩或部署。

## 剧情必须通过

- 从 S01 能到达每个节点与全部四个结局；非结局节点没有断路或无限循环。
- S08 A 和 B01 A 才建立恋爱关系；朋友线 F01/E03 不播放情侣送别、分手或共同生活。
- S07 B 的“考后说明”在 S08 兑现，不拖到分数出来后再冒充兑现。
- S07 未打过勾的路线不出现打勾闪回；S01 没有共听的路线不出现共听回忆。
- S02 不同笔记图案在 E01 中正确复现；归还笔记后，道具不再留在男主包里。
- S12 接班并提前改约可以到圆满，不把关照同事当作不爱对方。
- B06 道歉后没有兑现，R 仍为未修复；B10 必须继续进入 B11，而不是直接跳到 E01。
- B11 实际持续履约后可以修复；反复爽约不能无限用同一句道歉重置。
- D01 是坦诚告别，D02 是关系耗尽，E03 是没开始过；三者不能混用同一段分手对白。
- D01/D02 在不同时间进入时采用正确年龄、房间与生活物件。
- E01 同住和分别住都为圆满；没有强制求婚、生育或同居才能过关。
- E02 在分开多年后小梦已婚，重逢不提供越过其婚姻边界的复合选项。

## 呈现必须通过

- 每次推进主要更新一条气泡；前一条可从对白日志找回，不堆在画面里。
- 同一画面连续对白不重新请求背景，不卸载整个场景，不闪白、不重置人物位置。
- 同地点分支切换不强制黑屏；确实跨地点时淡出、短字幕、淡入。
- 背景先准备好再换；网络失败可重试，也能明确选择简化画面继续。
- 选项回应读完才跳转；每个选项都有已编写的回应，不只是修改数值。
- 所有选项无倒计时。气泡尾巴指向正确人物/手机源，不遮住眼睛或核心道具。
- 字体在普通桌面上清楚可读，调到 28px 不溢出；窄屏不把全部内容缩成小字。
- 29 张背景是实际不同的环境或必要时代变体，不能将一张校园图复制给大部分场景。
- 插画角色有可辨识五官；脸型、发型、校服与年龄连续。
- 本次参考插画不得误标为《后来呢》已经完成的新场景。

## 输入必须通过

- 未开摄像头可以用鼠标完成从封面到所有结局的流程。
- 允许摄像头后可以用手势完成同一流程，包含设置、菜单关闭与结局重开。
- 一次捏合只执行一个动作，保持捏合跨到新按钮不会自动触发。
- 手势等待松开不锁住鼠标；拒绝权限或识别失败后鼠标继续可用。
- 点击选项不会冒泡成“下一句”，漏掉回应开头。
- 快速双击、鼠标与捏合接近同时发生时，不重复提交选项或跨过阶段边界。
- 键盘 Enter/Space 与原生按钮语义保留，焦点可见。
- 切换输入方式、打开设置、失去跟踪都不改变当前剧情与存档。

## 存档必须通过

- 在对白中、刚选择后、回应中、转场中分别刷新，均能正确恢复。
- 恢复选择后的回应不会重复应用效果。
- 从检查点重选创建独立分支，不残留上条路线的事实。
- 完成结局收尾后才记录已读结局，不在进入结局时提前跳过内容。
- 存储不可用、容量不足或导入版本不兼容时有准确提示，不假称保存成功。
- 两个标签页写同一个槽位会检测冲突，不能静默互相覆盖。

## 可交付阶段

1. 文档定稿：剧情、节点表、人物与画面要求一致。
2. 可玩切片：至少一次真实选择、对应回应、同场分支和跨场转场完整可玩。
3. 全剧情通关：全部路线、状态和存档可用；未完成美术明确标识。
4. 正式美术版：基础背景、角色、关键道具、结局收尾素材齐备，完成逐幕视觉检查。
5. 发布候选：完成构建、浏览器实测与权限失败场景验证；发布另按用户后续要求执行。
